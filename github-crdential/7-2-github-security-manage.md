# 1. 보안 정책 설정 [`GH-100`]

보안 정책은 GitHub내 저장된 모든 리포지토리에 대한 안전한 사용을 위해 중요성이 최우선으로 지켜져야 하며, 에코시스템의 무결성을 유지한다. 이는 보안 정책이 어떤 과정을 거치며 진행되어야 하는지 혹은 설정 범위를 이해해야 하는지는 다음 세 가지의 조치가 필요하다.

1. 워크플로 안내 : 안전하고 표준화된 프로세스
2. 명확성 보고 : 취약성 공개를 위한 명확한 단계
3. 액세스 제어 : 위험을 제한하는 최소 권한 설정

> 리포지토리에서 조직이나 엔터프라이즈 수준에서 정책을 적용하여 엔터프라이즈 차원의 규칙은 균일성을 적용하고 조직 수준 설정을 사용하면 프로젝트 단위로 조정할 수 있다.

# 2. 보안 문서화 [`GH-100`]

보안 문서화는 사용자가 지원하는 버전, 문제를 보고하는 방식과 법적 고지 사항 또는 알려진 위험을 사용자에게 알릴 수 있는 `SECURITY.md`와 `기타 커뮤니티 파일`들을 통해 프로젝트의 투명성을 향상시키는 주요 커뮤니티 파일을 인식한다.

## 2.1 기타 커뮤니티

GitHub는 프로젝트 투명성을 향상시키기 위한 주요 커뮤니티를 구성하고 외부 사용자와의 협업 표준화를 기여한다.

* 다음 목록의 파일들의 이름과 목적은 다음과 활용된다. [`권장`]
  * `CODE_OF_CONDUCT.md` : 커뮤니티 행동 표준
  * `CONTRIBUTING.md` : 기여 지침 방식
  * `DISCUSSION category forms` : 커뮤니티 토론 위한 사용자 지정 템플릿
  * `FUNDING.yml` : 스폰서 옵션 목록 표시
  * `GOVERNANCE.md` : 사용자간 의사 결정 구조 및 흐름도를 설명
  * `ISSUE / Pull Request + config.yml` : 문제 및 검토 요청 표준화
  * `README.md` : 프로젝트 소개 및 설명
  * `SUPPORT.md` : 도움말 리소스를 제공

## 2.2 보안 설정 및 적용

팀 규모에 따라 신뢰와 제어를 선택하여, 소규모 부터 대규모 까지의 광범위한 사용 권한을 사용할 수 있지만 규모가 확장될 수록 고수준의 엄격한 정책 설정 및 적용이 필요하다. 이는 계단식 구조 형태의 권한을 부여하여 사전의 리스크를 방지함을 목적으로 진행해야한다.

### 2.2.1 구성 수준

* 조직(`Org-Level`) : 설정 > 멤버 권한
* 기업(`Enterprise-Level`) : 기업 > 정책 > 저장소 정책

> [!CAUTION]
> **엔터프라이즈 규칙은 조직 규칙을 재정의하며, 조직 소유자는 변경 불가한 설정을 임의로 설정할 수 없다.**

> [!IMPORTANT]

# 3. 사용 가능한 보안 도구 [`GH-100`]

모든 리포지토리는 `액세스 제어`, `SERCURITY.md`, `Dpendabot 경고 및 업데이트`, 검토에 도구를 포함하며, 고급 보안에 속하는 `코드 검사`, `비밀 검사`, `종속성 검토`가 해당된다.

## 3.1 GitHub를 사용한 엔터프라이즈 보안 강화

> GitHub의 엔터프라이즈 기능은 보안 상태 및 규정 준수를 강화한다.

* 보안 기능
  * GitHub GHAS(Advanced Security): 코드 검사, 비밀 검사, 종속성 검토
  * 보안 구성: 모든 리포지토리에서 일관된 설정 적용
* 규정 준수 지원
  * 규정 준수 보고서: 감사 및 규정 요구 사항에 사용할 수 있는 `SOC 1 ~ 2 유형 2`, `ISO/IEC 27001:2013 인증`

### 3.2.2 GitHub 지원에 문의

> 공용 리포지토리의 경우 캐시된 인덱스가 지속될 수 있다.

#### 지원 프로세스

* `.gitignore` 사용
* `GitHub 비밀` 또는 `비밀 관리자`를 활성화하여 비밀 저장
* `GitGuraian` 또는 `TruffleHog`로 정기적으로 스캔 진행

### 3.3.1 보안 소프트웨어 개발 사용 및 규정 준수 보장

> **다음 표와 같이 각 정책은 보안 및 유용성의 균형을 유지하도록 설계되었으며, 최소한의 제한에서 고도로 제어되는 환경에 이르기까지 다양한 옵션을 제공한다. 이는 제어 수준으로 분류된 다양한 보안 정책에 대한 개요를 제공한다.**

| 수준 | 권장 정책 및 기능                                                                           | 사용 사례                                 |
| ---- | ------------------------------------------------------------------------------------------- | ----------------------------------------- |
| 낮음 | 보안 권고 및 코드스캔, Dependabot 경고, 분기 보호 규칙[`선택`]                              | 보안 사례를 통해 유연성이 필요한 팀       |
| 보통 | 필수 분기 보호, 커밋 서명, 조직 전체 보안 정책, 웹후크 모니터링                             | 개발자 자율성을 가진 거버넌스가 필요한 팀 |
| 높음 | SAML SSO 및 2FA 적용, 표시 여부 및 포킹 제한, 필수 PR 승인, 강제 푸시 방지, CI/CD 보안 확인 | 엄격한 규정 준수 요구 사항이 있는 조직    |

### 3.3.2 GitHub Enterprise의 주요 보안 및 규정 준수 기능

1. **보안 코드 개발**
   * **코드 검사** : CodeQL을 통해 취약성을 자동으로 검색
   * **비밀 검사** : 하드 코딩된 비밀들을 누출을 방지
   * **종속성 검토 및 Dependabot** : 취약한 종속성을 식별하고 업데이트
2. **규정 준수 정책 적용**
   * **분기 보호 규칙** : PR 검토, 상태 검사 및 서명된 커밋이 필요
   * **보안 규칙 집합** : 여러 리포지토리에 대한 정책을 적용
   * **감사 로그 및 API 모니터링** : 활동 및 변경 내용을 추적
3. **액세스 및 인증 제어**
   * **SAML SSO 및 2FA 적용** : 모든 사용자에 대한 엄격한 인증 방식
   * **리포지토리 표시 유형 제한** : 포크하거나 복제할 수 있는 사용자를 제어
   * **Fine-Grained 접근 제어** : 팀 또는 프로젝트당 역할을 할당

### 3.3.3 다른 보안 및 규정 준수 프로필을 사용하는 경우

* **신생 기업** 및 **Agile Temas** : 분기 보호, Dependabot 및 비밀 검사를 사용하여 제어를 조정
* **기업** 및 **규제 산업** : SAML SSO, 감사 로깅, 보안 규칙 집합 및 엄격한 저장소 제어를 통해 높은 수준의 제어를 제공
* **오픈 소스 프로젝트** : 코드 검사, 중속성 업데이트 및 커뮤니티 지침을 사용하여 낮음에서 보통으로 제어

### 3.3.4 조직 및 엔터프라이즈 정책 정의

> **조직 정책 및 엔터프라이즈 정책은 거버넌스, 액세스 및 워크플로 규칙을 설정하여 보안 및 규정 준수를 보장한다.**

#### 주요 측면

1. **보안 및 액세스 제어** : SAML SSO, 2FA, `RBAC`, 리포지토리 공개 여부
2. **규정 준수 및 거버넌스** : 감사 로깅, 분기 보호, 커밋 서명
3. **개발 워크플로 및 자동화** : PR 승인, 보안 규칙 집합, 작업 정책
4. **코드 종속성 보안** : 코드 검사, 비밀 검사, Dependabot, 작업 제한

> [!NOTE]
> **[RBAC](https://moainfor.co.kr/rbac%ec%97%ad%ed%95%a0-%ea%b8%b0%eb%b0%98-%ec%a0%91%ea%b7%bc-%ec%a0%9c%ec%96%b4%eb%9e%80/)는 역할 기반 액세스 제어[`Role Based Access Control`] 이름으로 사용자에게 직접 권한을 부여하는 대신, 역할[`Role`]을 통해 주어진 권한 범위외 접근을 통제함 으로써 `보안 강화`, `관리 효율성 증대`, `규정 준수 용이성`, `유연성 및 확장성`에 대한 기대효과를 불러올 수 있다.**
