# 1. GitHub EMU (Enterprise Managed User) [`GH-100`]

GitHub EMU는 개별 사용자가 아닌 회사에서 소유한 GitHub Enterprise Cloud 전용 계정으로 회사의 관리자는 이러한 계정을 제어와 관리 및 감사를 통해 IdP에 GitHub Enterprisce 계정을 연결할 수 있다. Microsoft Entra ID 또는 OKta 에서 사용자 프로비저닝 수명 주기를 중앙에서 관리하고 멤버 및 계약자를 위한 진정한 Single Sign-On 환경을 구축할 수 있다. 이는 원할하게 작동하도록 관리자는 EMU 계정 및 해당 개인 리포지토리에 대한 완전한 관할권을 갖게된다.

회사는 이러한 EMU 계정을 소유하므로 회사의 관리자는 엔터프라이즈 내의 모든 조직에 EMU 액세스 권한을 부여할 수 있으며, 연결된 IdP에서 사용자 이름, 표시 이름 및 전자 메일을 포함하여 EMU의 프로필 정보를 제어할 수 있다. 이것은 EMU 계정을 사용함에 따라 GitHub의 IdP에서 수동으로 복제해야 하는 작업 수를 최소화할 수 있다.

IdP에서 프로비저닝을 사용하도록 설정하면 다음 작업을 수행할 수 있다.

* 팀 멤버 자격 및 리포지토리 액세스 관리
* 프로필 및 개인 데이터 제어
* GitHub EMU에서 팀 및 사용자 멤버십에 IdP 보안 그룹을 프로비저닝, 업데이트 및 디프로비저닝
* SSO를 사용하여 인증 간소화

## 1.1 엔터프라이즈 내에서 관리되는 사용자 액세스

> **EMU 액세스, 권한 및 제한 사항에 대해 언급한 내용 외에도 다음은 GitHub Enterprise 내에서 관리되는 일반 사용자 간의 차이점이다.**

|                | **GitHub EMU**                                                                                                                                    | **GitHub Enterprise Account**                                                                |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **소유권**     | ID 공급자에 대해 생성되고 제어                                                                                                                    | 안전한 엔터프라이즈 액세스를 보장하기 위해 GitHub에 여러 권한 부여 및 인증 이니셔티브가 필요 |
| **회원 자격**  | 자동화된 사용자 프로비너닝은 GitHub 팀과 IdP 그룹 멤버 자격을 동기화                                                                              | 관리자는 GitHub에서 엔터프라이즈 조직의 팀에서 사용자 멤버 자격을 관리                       |
| **정책**       | 계정의 모든 사용자에게 적용되는 엔터프라이즈 수준에서 정책 생성 가능                                                                              | 사용자는 GitHub 사용자 정책 준수를 확인 필요                                                 |
| **감사 로그**  | 엔터프라이즈 소유자는 GitHub.com 관리되는 사용자의 모든 작업을 감사 가능                                                                          | 엔터프라이즈 계정에서 발생하는 감사 로그 활동만 검토에 사용될 수 있음                        |
| **프라이버시** | EMU 사용 엔터프라이즈에 대한 공용 리포지토리가 존재하지 않음                                                                                      | 엔터프라이즈 사용자는 공용 리포지토리를 생성 가능                                            |
| **SSO**        | 사용자를 위한 진정한 Single Sign-On 환경                                                                                                          | 사용자가 로그온하는 데 필요한 여러 인증 단계                                                 |
| **메타데이터** | 엔터프라이즈는 사용자 GitHub 메타데이터를 제어하고, 관리되는 사용자는 수정 불가 또한 메타데이터에는 전자 메일 주소, 표시 이름 및 사용자 이름 포함 | 엔터프라이즈 사용자는 자신의 계정을 만들고 전자 메일을 제공하여 GitHub 핸들을 선택           |

# 2. 인증 및 사용자 프로비저닝 [`GH-100`]

관리되는 사용자를 사용하여 IdP에서 직접 GitHub.com 엔터프라이즈 구성원에 대한 사용자 계정을 프로비전한다. 엔터프라이즈의 리소스에 액세스하려면 모든 멤버가 IdP를 통해서만 인증해야 하며 ID 및 액세스를 관리하고자 할 경우 GitHub.com IdP 및 엔터프라이즈에서 애플리케이션을 구성해야 한다. 인증에는 SAML(`Security Assertion Markup Language`) SSO가 필요하며 사용자 프로비저닝에는 SCIM용 시스템이 필요하다. 구성을 완료한 후 IdP는 다음 변경 사항을 수행할 때마다 GitHub.com과 통신해야 한다.

* IdP의 사용자에게 애플리케이션 할당 IdP는 GitHub.com 엔터프라이즈의 구성원으로 사용자 계정을 만들고 사용자에게 알림 이메일을 보낸다.
* IdP에서 사용자의 ID와 연결된 정보를 업데이트하고, GitHub.com 사용자의 계정을 업데이트 진행한다.
* 사용자로부터 애플리케이션을 할당 해제하거나 IdP에서 사용자 계정을 비활성화 하고, IdP는 GitHub.com과 통신하여 SAML 세선을 무효화해 멤버의 계정을 비활성화 처리 진행한다.

# 3. EMU 계정에 대한 기타 사용 사례 [`GH-100`]

#### 신입 직원 온보딩

직원들은 조직, 부서 및 팀 전체에서 지속적으로 회사에 가입하고 있습니다. 관리자는 첫 날 아침에 필요한 모든 권한이 있는 새 직원에 대한 EMU 계정을 프로비전할 수 있습니다. 또한 EMU 계정을 사용하면 회사 전자 메일과 일치하는 GitHub 핸들을 할당하여 모든 시스템에서 쉽게 식별할 수 있습니다. 이 모든 설정은 GitHub가 아닌 IdP 내에서 발생합니다. 이 구성의 이점은 이러한 설정을 혜택, HR 및 비용 시스템과 동일한 자동 흐름으로 구성하여 빠르고 효율적이며 일관된 온보딩을 만드는 것입니다.

#### 직원 오프보딩

온보딩과 달리 직원이 회사를 떠날 때 관리자는 나머지 작업 액세스 및 시스템을 해제하는 데 사용되는 흐름과 동일한 흐름으로 GitHub 계정을 즉시 일시 중단할 수 있습니다. 이 턴오프에는 HR, 이메일, 내부 문서 및 혜택이 포함됩니다. IdP는 EMU를 관리하므로 직원이 퇴사할 때 중요한 소스 코드에 대한 액세스를 제거하는 효율적이고 빠르고 안전한 방법을 만듭니다. 이 자동 턴오프는 느린 GitHub 액세스를 방지합니다.

#### 실수로 인한 IP 누수 줄이기

오픈 소스 소프트웨어 기여가 증가함에 따라 직원들은 하루 종일 다른 사용자 ID와 권한이 있는 프로젝트 간에 전환해야 할 수 있습니다. 이 경우 잘못된 자격 증명을 사용하여 프로젝트에 실수로 IP(지적 재산권) 누수 및 기여가 발생할 수 있습니다. EMU는 현재 계정을 명확하게 식별하고 직원이 실수로 개인 또는 오픈 소스 리포지토리에 IP를 노출할 수 없도록 하여 이러한 위험을 줄입니다. 이 설정은 회사, IP 및 직원이 실수로 누출되는 것을로부터 보호합니다.

#### 컨설턴트 관리

EMU 계정으로 신규 직원에게 액세스 권한을 부여하는 것과 마찬가지로 컨설턴트는 회사의 IdP를 통해 EMU 계정에 대한 액세스 권한을 부여할 수 있습니다. 프로젝트가 완료되면 다른 모든 항목에 대한 액세스 권한을 잃게 되는 것과 동일한 흐름을 사용하여 GitHub에 대한 액세스 권한을 잃게 됩니다. 이 자동 제거는 계약이 만료된 후 며칠 또는 몇 주 동안의 액세스를 방지합니다. 또한 컨설턴트가 동시에 여러 클라이언트와 작업하는 경우 EMU 계정을 사용하여 컨설턴트가 실수로 회사의 IP를 다른 클라이언트의 리포지토리로 누수할 수 없습니다. 이 설정을 사용하면 회사의 소스 코드 및 IP에 대한 액세스를 엄격하게 제어하면서 느린 액세스 또는 우발적인 IP 누출을 줄일 수 있습니다.
