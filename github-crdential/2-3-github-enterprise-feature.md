# 1. GitHub 엔터프라이즈 기능 [`GH-100`]

GitHub 엔터프라이즈 관리자는 안전하고 확장 가능한 개발 환경을 설정할 책임을 부여되고 있으며, 엔터프라이즈의 유지 관리 기능과 자동화 기능을 구분하는 방법과 효율적인 협업을 위해 조직을 구성하는 과정을 다룬다.

## 1.2 유지 관리 및 자동화

> **GitHub 엔터프라이즈에는 GitHub 팀의 모든 기능과 다음과 같이 분류된 엔터프라이즈별 기능이 포함되어 있다.**

* **유지 관리** : 보안, 액세스 및 지원을 개선하는 기능
* **자동화** : 개발자를 위한 수동 워크로드를 줄이고 대규모로 코드 품질을 개선하는 기능

# 2. 개발자 워크플로 표준 설정 [`GH-100`]

> **일관성, 보안 및 확장성을 보장하기 위해 GitHub Enterprise 조직은 다음 워크플로 표준을 따라야 한다.**

## 2.1 협업 모델

| **워크플로**   | **사용 시기**                     |
| -------------- | --------------------------------- |
| **포크 앤 풀** | 오픈 소스 또는 조직 간 공동 작업  |
| **분기**       | 공유 리포지토리 내의 내부 팀 개발 |

## 2.2 브랜칭 규약

* 일관된 이름 지정 체계를 채택
* `main` 또는 `develop`를 CI/CD 파이프라인의 안정적인 통합 분기로 사용

## 2.3 규칙 집합

> **`규칙 집합`은 대규모 정책을 적용하기 위한 권장 메커니즘으로 기존 분기 보호 규칙과 달리 규칙 집합을 사용하면 여러 리포지토리 및 팀에서 정책을 중앙에서 관리할 수 있다.**

### 2.3.1 규칙 집합의 이점

* 리포지토리 정책에 대한 중앙 집중식 제어
* 팀 간 적용 일관성
* 성장하는 조직을 위한 확장성
* 계층화된 조합을 통한 세분화된 유연성

### 2.3.2 규칙 집합 및 분기 보호 결합(레거시 지원)

* 규칙 집합을 기본 메커니즘으로 사용
* 리포지토리별 예외에 대한 계층 분기 보호 규칙
* 최소 겹치지 않도록 설정하여 정책 충돌을 방지

# 3. 유지 관리 기능을 통한 보안 액세스 및 작업 지원 [`GH-100`]

> **유지 관리 기능은 사용자 환경의 마찰을 줄이고, 보안 액세스 제어를 보장해 하이브리드 클라우드 환경을 지원한다.**

## 3.1 주요 유지 관리 기능

| **특징**                            | **설명**                                              |
| ----------------------------------- | ----------------------------------------------------- |
| **엔터프라이즈 지원**               | GitHub에서 직접 지원                                  |
| **SAML/SCIM 인증**                  | ID 및 액세스 관리를 중앙 집중화                       |
| **GitHub Connect**                  | Enterprise Cloud와 Server 간의 통합을 사용하도록 설정 |
| **GitHub Pages에 대한 액세스 제어** | 내부 협력자만 문서 접근성을 제한                      |

### 3.1.1 구성 안내

#### SAML SSO 사용

1. IdP(ID 공급자)를 GitHub에 연결
2. 조직 설정에서 SAML 인증 필요를 선택
3. 로그온 URL, 발급자 및 인증서를 제공

#### GitHub 페이지 액세스 제한

1. 프라이빗 리포지토리 설정으로 이동
2. GitHub Pages 표시 유형을 Private으로 설정
3. 액세스할 수 있는 공용 URL이 없는지 확인

#### GitHub Connect 사용

1. GitHub Enterprise Server 및 GitHub.com 모두 로그인 진행
2. 서버 설정에서 GitHub Connect 사용을 선택
3. 통합 검색 및 기여를 위한 연결할 조직 선택

## 3.2 안전하고 확장 가능한 워크플로 자동화 기능

> **자동화 기능은 사용자 오류를 줄이고 코딩 표준을 적용하여 CI/CD를 간소화하는 데 도움이 된다.**

### 3.2.1 핵심 자동화 기능

| **특징**                           | **설명**                                    |
| ---------------------------------- | ------------------------------------------- |
| **GitHub GHAS(Advanced Security)** | 코드에서 취약성 및 비밀을 검색              |
| **GitHub 작업 시간**               | 빌드, 테스트 및 배포를 자동화               |
| **자동 보안 업데이트**             | 종속성을 안전하게 유지하고 최신 상태로 관리 |

### 3.2.2 자동화 사용량 추적

#### GitHub GHAS(Advanced Security)

1. 엔터프라이즈 > 설정으로 이동
2. GitHub Advanced Security에서 사용자 사용량을 검토
3. 설정한 제한치에 근접하면 팀별 사용량을 평가하고 우선 순위를 지정

#### GitHub Actions

1. 엔터프라이즈 > 설정 > 청구 > GitHub Actions로 이동
2. 월별 50,000분 및 50GB 스토리지에 대한 사용량을 모니터링
3. 실행기 사용 비용 참고
   * Linux : 1배
   * Windows : Linux의 2배
   * macOS : Linuxd의 10배

# 4. GitHub Enterprise CI/CD 전략 [`GH-100`]

> **GitHub Enterprise를 사용하면 GitHub Actions 및 외부 도구와의 통합을 사용해 안전하고 확장 가능한 CI/CD 사례를 사용할 수 있다.**

#### 주요 기능

* **GitHub Actions** : YAML에서 워크플로를 정의하여 GitHub 이벤트에 의해 트리거되는 빌드, 테스트 및 배포를 자동화
* **빌드 파이프라인** : 코드 컴파일, 단위 테스트, 아티팩트 생성 및 PR 효율성 검사를 자동화
* **자동화 테스트** : 병합하기 전에 품질을 보장하고자 위해 단위, 통합 및 보안 테스트를 통합
* **CD(Continuous Delivery)** : 선택적 승인을 통해 스테이징 또는 프로덕션에 자동으로 릴리스
* **도구 체인 유연성** : 웹후크 및 GitHub Marketplace 앱을 통해 Jenkins, CircleCI, Azure Pipelines 등 지원
* **릴리스 자동화** : CI 워크플로에서 변경 로그 및 버전이 지정된 아티팩트로 태그가 지정된 릴리스를 트리거
* **CI/CD 보안** : Dependabot, 비밀 검사 및 규정 준수 검사를 파이프라인에 직접 통합한다.
* **모니터링 및 알림** : 경고를 구성하고 관찰성 도구를 통합해 배포 상태 및 성능을 추적

#### 튜토리얼

* 시작하기
   * 배포를 자동화하려면 다음을 수행합니다.

1. .github/workflows/ 리포지토리에 디렉터리를 만듭니다.
2. GitHub Actions YAML(예: ci-cd.yml)을 사용하여 CI/CD 파이프라인을 정의합니다.
3. 비밀을 사용하여 자격 증명을 안전하게 관리합니다.
4. 배포 게이팅을 위해 환경 및 수동 승인을 활용합니다.

* **조직 상태 모니터링**
  * 인사이트를 사용하여 사용 추세, 공동 작업 패턴 및 위험 영역을 식별합니다.**

* **조직 활동 인사이트**
  * 끌어오기 요청, 문제 및 코드 언어의 추세를 봅니다.
  * 팀 배포 및 개발자 참여를 평가합니다.

* **종속성 인사이트**
  * 타사 종속성에서 취약성을 식별합니다.
  * 라이선스 위험을 검토하고 보안 상태를 평가합니다.

## 6.3 관리 지원 범위

> **GitHub 지원은 일반적으로 계정, 보안 및 남용의 세 가지 영역에서 문제를 지원하고 내부 관리자는 인프라, 내부 도구 또는 외부 인증과 관련된 작업을 처리한다.**

* **계정 문제** : ID를 확인하고 액세스를 복원하여 지원은 2단계 인증 자격 증명 손실과 같은 계정 액세스 문제를 해결하는 데 도움이 된다.
* **보안 인시던트** : 손상된 계정의 손상도를 완화하고, 리포지토리 변경 내용을 롤백을 진행해 보안 복구를 지원할 수 있다.
* **남용 사례** : 지원은 괴롭힘 또는 부적절한 콘텐츠와 같은 GitHub 약관 위반을 조사하고 필요에 따라 사용자 또는 콘텐츠를 제거할 수 있다.

> [!IMPORTANT]
> **관리자는 인프라 구성, CI/CD 통합, 타사 인증 시스템, 내부 스크립팅, 하드웨어 설정 및 즉각적인 온-프레미스 문제 해결을 담당한다.**

# 7. 엔터프라이즈 배포 크기 조정 [`GH-100`]

> **팀 확장 또는 새로운 계약자 계약으로 인해 GitHub Enterprise 조직이 성장함에 따라 관리자는 보안 액세스 보장, ID 수명 주기 관리, 규정 준수 모니터링 및 배포 파이프라인 최적화를 담당한다. 이는 안전하고 효율적으로 크기를 조정하는 데 도움이 되는 주요 GitHub Enterprise 기능 및 거버넌스 도구를 다룬다.**

## 7.1 SSO(Single Sign-On)를 사용한 액세스 보호

> **중앙 집중식 ID 제어를 유지하고 사용자 관리를 간소화하려면 Okta 또는 Microsoft Entra ID와 같은 IdP에서 SAML 기반 SSO를 사용하도록 설정한다.**

> [!TIP]
> * **조직의 피플 탭에서 SAML ID 연결 섹션에서 개별 SAML 자격 증명을 검토하고 해지할 수 있다.**
> * **팀 동기화를 사용하는 경우 사용자의 SSO ID를 해지하려면 IdP 그룹에 매핑된 모든 팀에서 자동으로 제거된다.**

## 7.2 SCIM 및 API를 사용한 ID 관리 자동화

> **GitHub API를 활용하여 사용자 프로비저닝 및 프로비저닝 해제를 자동화하고, 보안 정책을 적용해 기업 전체에서 액세스를 모니터링한다.**

#### 수명 주기 자동화에 SCIM API 사용

> **SCIM 표준은 RESTful JSON 요청을 통해 ID 워크플로를 간소화한다. 지원되는 내용은 다음과 같다.**

* Microsoft Entra ID
* Okta
* OneLogin

#### API 사용에 대한 책임

> **비효율적인 폴링 패턴을 피하고, 웹 후크, GitHub Apps 또는 GitHub Actions를 사용하여 자동화를 트리거 한다. 감사 로그로 API를 사용하는 경우에는 장기 보존 및 규정 준수 보고를 위해 Splunk 또는 ELK와 같은 외부 SIEM 시스템에 로그를 저장한다.**

```sh
curl -H "Authorization: Bearer YOUR_TOKEN" \
https://api.github.com/enterprises/YOUR_ENTERPRISE/audit-log
```

## 7.3 엔터프라이즈 감사 및 GraphQL API 준수 모니터링

> **엔터프라이즈 계정 API 및 감사 로그 API(`GraphQL만 해당`)를 사용하여 변경된 중요 내용을 추적할 수 있으며 필요한 데이터만 가져오거나 프로그래밍 방식으로 엔터프라이즈 설정을 변경할 수 있다.**

* 리포지토리 또는 설정 액세스
* 사용자 또는 역할 변경
* 앱 권한 업데이트

## 7.4 Enterprise Apps를 사용하여 앱 거버넌스 제어
