# 1. GitHub에서 제공하는 사용자 ID 인증 및 권한 부여

기존에 사용자 인증은 사용자 ID와 암호를 사용하여 수행해왔으며, 암호는 인즈의 단일 요소 형식이다. 단일 요소 인증의 근본적인 문제로 로그온 정보를 아는 악의 행위를 하는 사용자를 보다 쉽게 가장할 수 있기 때문에 사용자 계정의 보안 위반을 방지하고자 GitHub에서는 보안 모범 사례를 승격하는 데 사용할 수 있는 인증 도구가 있다. 조직 내의 모든 GitHub 사용자에게 보안 정책을 적용할 수 있다.

# 2. 사용자 ID 및 액세스 관리

인증은 엔터프라이즈의 소프트웨어 개발 에코시스템에 대한 게이트웨이이다. GitHub와 모든 사용자의 상호 작용은 ID 확인으로 시작하여 개별 계정은 사용자 이름 및 암호를 사용할 수 있지만 엔터프라이즈는 보안으로 2FA(`2단계 인증`) 또는 암호 및 생체 인식 로그인과 같은 고급 방법을 요구한다.

## 2.1 GitHub Enterprise의 최신 인증

> 안전하고 간소화된 인증 환경을 보장하기 위해 GitHub는 ID 관리 시스템과 통합되는 여러 최신 방법을 지원한다.

### 2.1.1 패스키 및 웹인증

* 패스키는 물리적 디바이스에 연결되고 피싱에 강한 암호 없는 로그인 방법이다.
* WebAuthn은 YubiKey와 같은 생체 인식 요소 및 하드웨어 토큰을 지원한다.
* 이러한 메서드는 자격 증명 기반 공격을 크게 줄이고 로그인 UX를 개선한다.

### 2.1.2 GitHub Mobile 2FA

사용자는 빠르고 안전한 승인을 위해 푸시 알림을 지원하는 GitHub Mobile을 사용하여 인증할 수 있으며 워크플로를 방해하지 않고 2FA를 향상시킬 수 있다.

### 2.1.3 OAuth 및 GitHub App

* OAuth 앱은 GitHub의 OAuth 2.0 흐름을 사용하여 사용자를 인증하고 외부 애플리케이션에 범위가 지정된 액세스 권한을 부여한다.
* GitHub Apps는 세분화된 사용 권한으로 개별 설치로 인증되며 CI/CD 및 자동화 파이프라인에 적합하다.

### 2.1.4 엔터프라이즈 관리 사용자(Enterprise Manage User)

GitHub Enterprise Cloud에서 EMU는 Idp(ID 공급자)를 통해 인증이 엄격한 단계에서 수행하도록 한다.

* 엔터프라이즈 관리 계정에 대한 액세스으로만 범위를 좁혀 제한한다.
* ID, 자격 증명 및 세션 정책에 대한 중앙 집중식 제어를 적용한다.

# 3. SAML SSO를 사용한 조직 관리

엔터프라이즈급 인증의 기본 기능 중 SAML SSO(`Single Sign-On`)으로 Idp를 GitHub와 연결하여 사용자가 하나의 자격 증명 집합을 사용하여 서비스 간에 로그인할 수 있도록 하며 조직 또는 엔터프라이즈 리소스에 대한 액세스 권한을 부여하기 전에 사용자 ID를 확인한다.
