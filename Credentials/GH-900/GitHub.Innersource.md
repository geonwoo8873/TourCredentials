# GitHub Innersource Management

오픈 소스 소프트웨어의 장점은 상표 개방성이 높아 누구나 참여할 수 있으므로 활동 지표는 높지만, 재산적 가치를 가지는 소프트웨어는 IP[`지적 재산`]의 프라이버시를 중시하는 폐쇄된 시슽템을 통해 액세스를 제한한다. 독점 소프트웨어에 상당한 투자를 진행한 기업의 책임자 입장에서는 사내 기술이 아니라더라도 다양한 형태와 규모의 회사가 업계 내 경쟁력을 우위를 가지고자 하는 목표를 위해 자체 소프트웨어와 IP등 다양한 형태의 자산을 만들고 유지 관리한다.

그러나 오픈 소스에서 사용되는 패턴의 중요성을 비중이 높고 이와 같은 패턴에서 소스 코드 표시 유형, 프로젝트 버그 인식 및 기능 요청 투명성 등이 있기 때문에, 외부 참여 통합을 간소화하는 끌어오기 요청 모델을 선호한다. 개발 부서에 이러한 이점을 도입하길 원하는 기업의 귀중한 소프트웨어를 오픈을 꺼려하기 때문에 이를 보완하는 제공 기능이라고 생각하면 되며 명칭은 `Innersource`가 필요하다는 것이다.
