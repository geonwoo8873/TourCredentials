# GitHub Repository Security Manage

## 보안 GitHub 리포지토리 유지 관리 과정

애플리케이션 보안의 중요성은 보안 개발 전략을 계획할 때 고려해야할 문제와 직결되고 외부에 정보가 공개되지 않도록 보호해야 하지만 적절한 경우에만 변경되거나 삭제되도록 해야 한다. 또한 데이터는 액세스하는 사용자와 데이터에 액세스할 수 잇는 올바른 권한이 있는지 명확한 검증이 되어야 하며, 기록 또는 보관 데이터 또는 로그를 통해 문제가 있을 때 증거를 찾을 수 있어야 한다.

해당 애플리케이션을 빌드하고 배포하는 데는 여러 가지 측면이 존재하며, 고래야할 사항은 다음과 같다.

* **일반적인 지식 문제가 발생한다.** 다수의 개발자와 그외 이해관계자들은 보안을 숙지하고 있는 형태로 가정하지만 현실적으로 그렇지 않으며, 사이버 보안은 지속적으로 보완과 진화하는 분야에 속하기 때문에 지속적인 교육 및 교육 프로그램은 필수적이다.
* **코드를 정확하고 안전하게 만들어야 한다.** 코드가 올바르게 생성되고 필요한 기능을 안전하게 구현해야 하는 목표를 가지고 있기 때문에, 보안을 염두에 두고 기능이 설계되어 있는지 모니터링이 필요하다.
* **애플리케이션은 규칙 및 규정을 준수해야 하며, 코드가 필요한 규칙 및 규정을 준수하는지 검증을 진행한다.** 코드를 빌드하는 동안 규정 준수를 테스트한 다음 배포 후에도 주기적으로 재 테스트 과정을 거치는 것이다.

### 모든 단계의 보안

보안은 향후 애플리케이션 또는 시스템에 추가할 수 있는 것이 아닌 소프트웨어 개발 수명 주기의 전과정에서 속해야 하며, 이 개념은 중요한 애플리케이션 및 중요한 또는 극비 정보를 처리하는 애플리케이션에 더욱 중요하다. 실사례를 바탕으로 팀이 개발한 내용에 대한 책임을 보다 명확하게 묻기 위함으로 프로세스는 왼쪽으로 이동하거나 개발 수명 주기 초기에 완료해야 한다. 배포시 최종 게이트에서 이전 단계로 단계를 이동하면 실수를 방지할 수 있을뿐만 아니라 더 빠른 대응이 가능하도록 이동이 가능하다.

또한 애플리케이션 보안 개념은 과거에는 개발자에게 중점을 두지 않았었다. 교육 및 교육 문제 외에도 조직에서 기능외 빠른 개발을 강조해왔고 그에 따른 비용 발생에 따른 외부적인 과정이 추가되기 때문에 생긴 현상이다. 그러나 현재는 DevOps 사례가 도이보디면 보안 테스트를 파이프라인에 더 쉽게 통합할 수 있도록 하고, 보안 전문가가 수행하는 작업이 아니라 보안 테스트는 일상적인 배달 프로세스의 일부뿐이다.

전반적으로 재작업 시간을 고려할 경우 개발 수명 주기의 앞부분에서 DevOps 사례에 보안을 추가하면 개발 팀이 문제를 빠르게 파악할 수 있으며, 문제를 보다 빠르게 인지할 수록 고품질의 소프트웨어를 개발하는 데 발생하는 전체적인 시간을 단축 시킬수 있는데 장점을 가지고 있다.
