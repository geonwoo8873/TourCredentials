## 1. GitHub 검색

수정을 시작할 단서를 제공하는 이벤트를 경험하지 못했거나 이러한 이벤트 다수를 프로젝트의 기록에서 확인할 수 있으며, 프로젝트의 리포지토리의 특정 단어를 검색하면 시작 지점을 확보할 수 있다. GitHub에서는 두 가지 방법을 사용할 수 있으며, 하나는 페이지 상단에서의 전역 검색과 다른 하나는 특저 리포지토리 탭에서 사용할 수 있는 범위 지정 검색이다. 이는 동일한 구문과 함수를 같은 방식으로 지원하지만 몇 가지의 차이가 존재한다.

### 1.1 전역 검색

> [GitHub Docs URL](https://docs.github.com/ko/enterprise-cloud@latest/search-github/searching-on-github)

전역 검색을 사용하면 완전한 검색 구문을 통해 GitHub 전체를 검색할 수 있다. 검색 결과는 포괄적이며 코드부터 문제, 마켓플레이스나 사용자까지 이르는 모든 항목을 포함하기 때문에 검색하고자 하는 프로젝트나 리포지토리에 대한 검색 방식은 주요 용어에 대한 언급을 찾는 것이 합리적인 방법이다.

### 1.2 컨텍스트 검색

컨텍스트 검색은 문제나 끌어오기 요청 같은 특정 탭에서 사용할 수 있으며, 이러한 검색은 현재 리포지토리로 범위가 지정되어 관련 형식 결과만 반환된다. 범위 지정의 이점은 사용자 인터페이스에서 작성자, 레이블, 프로젝트 같은 알려진 유형별 필터를 표시할 수 있다는 점이다. 이는 무언가를 찾을 때 선호하는 방법으로 필터 드롭다운을 통해 쉽게 상세 검색할 수 있다.

### 1.3 검색 필터 사용

완전한 검색 구문을 이용한 검색은 한정적이지 않은 방식으로 사용할 수 있지만 대부분의 검색은 몇 가지 일반적인 필터를 사용한다. 컨텍스트 검색 드롭다운에서 제공되기도 하지만 직접 입력하는 방식이 효율적일 수 있다.

| 쿼리                                  | 설명                                                         |
| ------------------------------------- | ------------------------------------------------------------ |
| is:open is:issue assignee:@me         | 현재 사용자에게 할당된 미해결 문제(@me)                      |
| is:closed is:pr author:contoso        | @contoso에서 생성한 종결된 끌어오기 요청                     |
| is:pr sidebar in:comments             | 설명에서 "사이드바"를 언급하는 끌어오기 요청                 |
| is:open is:issue label:bug -linked:pr | 연결된 끌어오기 요청이 없는 버그로 레이블 지정된 미해결 문제 |

# 2. 중요 시점 사용

중요 시점을 사용하면 스프린트, 제품 릴리스 또는 프로젝트 단계와 같은 공유 목표에 문제를 그룹화하고 요청을 끌어올 수 있다. 팀이 진행 사황을 추적하ㄷ고 모든 사람을 정렬하는 데 도움이 된다.

* 프로젝트와 마찬가지로 순서를 지정할 수 있어 우선 순위를 쉽게 설정하고 가장 중요한 마일스톤을 시각화할 수 있다.
* 각 마일스톤에 대한 진행률이 자동으로 추적되어 GitHub는 완료된 문제 또는 PR 수와 남은 문제 수를 보여 준다.
* 중요 시점은 별도의 릴리스 또는 단계로 진행되는 작업을 추적하는 데 특히 유용하다.

## 2.1 중요 시점 만들기

1. 리포지토리의 문제 카테고리 탭으로 이동
2. 상단 메뉴에서 마일스톤 선택
3. 새 중요 시점을 선택
4. 제목, 설명 및 기한(선택) 입력
5. 중요 시점 만들기 선택

## 2.2 문제에 중요 시점 할당 또는 끌어오기 요청

중요 시점을 GitHub Projects 레이아웃에 열로 추가하거나 중요 시점을 GitHub Projects 보드에 카드 형태로 표시할 수 있고, 프로젝트 계획 보드에서 직접 팀의 진행 상황을 시각화하고 관리할 수 있다.

* GitHub Projects의 중요 시점 또는 다음과 같은 고급 검색 쿼리를 사용하여 필터링할 수 있다.
    ```md
    is:open is:pr milestone:"Release v1.0"
    ```

# 3. 검색의 레이블 및 중요 시점

레이블 및 중요 시점은 팀이 문제를 구성하고 요청을 끌어오는 데 도움이 되는 메타데이터 도구이며, 검색 퀄리의 정확도도 향상된다.

## 3.1 레이블로 필터링

키워드를 사용하여 필터링하여 `label:` 문제 범위를 좁힐 수 있다.

```md
is:open is:issue label:bug
```
```md
is:pr label:"ready for review" author:@me
```

## 3.2 마일스톤으로 필터링

중요 시점은 문제를 그룹화하고 대상 릴리스 또는 목표를 향해 요청을 끌어오는 데 도움이 된다. 퀄리의 `milestone:` 키워드를 사용하여 특정 중요 시점 내의 항목을 반환한다.

```md
is:open is:issue milestone:"Sprint 1"
```

# 4. GitHub 블레임

`git blame`은 파일의 커밋 기록을 표시하는 명령으로 어떤 사용자가 무엇을 변경했는지에 대한 식별을 보다 쉽게 확인할 수 있게 하기 때문에 파일에서 작업을 수행한 사용자를 추적하여 입력한 내용이나 참여를 확인하는 과정도 쉬워진다.

# 5. 교차 링크 문제 및 커밋

GitHub가 공동 소프트웨어 프로젝트에 유용한 또 하나의 이유는 정보의 개별적인 부분을 연결하는 기능으로, 이 기능이 자동으로 실행될 때 있는데 대표적인 경우는 분기의 연속 커밋에서 끌어오기 요청을 생성할 때이다. 그 외의 경우에는 인터페이스에서 드롭다운 메뉴를 사용하여 끌어오기 요청이나 프로젝트를 문제에 수동으로 연결할 수 있다.

# 6. 저장된 회신

저장된 회신을 사용하면 문제에 신속하게 응답하고 미리 작성된 메시지를 사용하여 요청을 끌어올 수 있다. 특히 동일한 피드백이나 지침을 제공하는 프로젝트 유지 관리자에게 특히 유용하다.

## 6.1 저장된 회신 만들기 또는 편집

1. 우측 상단 프로필 사진 클릭하고 설정을 선택한다.
2. 좌측 사이드바에서 저장된 회신을 클릭한다.
3. 저장된 새 회신을 선택한다.
4. 제목과 메시지를 입력한다.
5. 회신 저장을 클릭한다.

# 7. 문제 템플릿

저장된 회신은 일반적인 응답에 유용하지만 문제 템플릿은 참가자가 새 문제를 만들 때 필요한 모든 정보를 제공하도록 하는 다른 방식의 방법이다.

* 문제 템플릿은 사용자에게 특정 필드를 채우거나 특정 질문에 미리 답변요청하는 메시지를 표시하여 필요한 세부 정보가 있는지 확인한다.
* 템플릿을 사용하면 문제가 제출되기 전에 구조화된 정보를 수집하여 유지 관리자가 "데이터 손실"을 방지할 수 있다.

## 7.1 담당자 추가

문제에 하나 이상의 사용자를 할당하거나 요청을 끌어오면 작업 챔임이 있는 사용자를 표시할 수 있다.

1. 문제를 열거나 요청 끌어오기
2. 우측 사이드바에서 담당자 선택
3. 드롭다운에서 하나 이상의 사용자 선택

> [!TIP]
> **검색에서 필터 부분을 `assignee:` 사용하여 자신 또는 다른 사용자에게 할당된 항목을 찾는다.

```md
is:open is:issue assignee:@me
```

# 8. 자동 링크된 참조

GitHub는 프로젝트 전역에서 다양한 항목을 더 쉽게 교차 링크할 수 있도록 단축 구문을 제공한다. 해당 끌어오기 요청이나 문제에 설명을 남기면 그에 대한 적절한 링크를 생성하여 자신의 ID 처음 7자 이상을 붙여넣은 커밋을 링크하는 기능도 제공한다.
