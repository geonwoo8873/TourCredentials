# Codespace

GitHub Codespace는 사용자가 프로젝트에 대한 사용자 지정 개발 환경을 구성할 수 있는 하나의 기능으로 프로젝트의 모든 사용자가 사용할 수 있는 반복 가능한 Codespace 환경을 구성을 만들 수 있다. Codespace 수명 주기는 생성 후 편집을 시작할 때와 종료하여 삭제를 할 때까지 유지되며, 활성화된 Codespace의 연결을 끊고 다시 연결해도 실행 중인 프로세스는 영향을 주지 않는다. Codespace를 중지하고 다시 시작하더라도 작업 진행한 내용에 대한 변경 부분은 손실되지 않는다.

## Codespace 생성

GitHub.com이나 Visual Studio Code[VSCode]에서 대부분 활용하며, 별도로 CLI를 이용해 간소화된 환경에서 생성할 수 있다. Codespace는 다음과 같이 여러 방법으로 생성할 수 있다.

* GitHub Template 또는 GitHub.com에 업로드된 템플릿 리포지토리에서 새 프로젝트를 시작
* 새 기능 작업을 위한 리포지토리의 분기에서 시작
* 오픈 되어 있는 끌어오기 요청에서 진행 중인 작업을 탐색
* 특정 시점의 버그를 조사하기 위한 리포지토리 기록의 커밋에서 시작

코드를 테스트를 위해 Codespace를 일시적으로 사용하거나, 동일한 Codespace로 돌아가 장기적인 실행 기능 작업을 수행할 수 있다. 리포지토리 또는 분기당 둘 이상의 Codespace 영역을 만들 수 있지만 이는 제한된 생성 가능한 최대의 수는 정해져 있기 때문에 다른 Codespace를 생성 하고 싶다면, 실행중인 Codespace를 삭제해야 새 Codespace를 생성할 수 있다.

>[!TIP]
> 새 프로젝트를 시작하는 경우 템플릿에서 Codespace를 만들고 반드시 GitHub의 리포지토리에 게시를 완료해야 한다.

프로젝트에서 작업할 때마다 새 Codespace를 만드는 경우에는 새 커밋이 GitHub에 있도록 변경 내용을 정기적으로 푸시해야 하며, 새 프로젝트에 장기 실행 Codespace를 사용하는 경우 작업을 시작할 때마다 리포지토리의 기본 분기에서 끌어오면 환경에서 최신 커밋을 가져올 수 있다. 이 워크플로는 로컬 환경에서 프로젝트를 작업하는 과정과 비슷하다.

### Codespace 변경 내용 저장

웹[Web]을 통해 Codespace에 연결하면, 자동으로 활성화된 저장을 제공하여 일정 시간이 지나면 변경된 내용을 저장한다. 데스크톱에서 실행 중인 Visual Studio Code 통해 Codespace에 연결하는 경우, 자동 저장을 필수로 설정해야 하는 과정이 추가되지만 작업은 클라우드의 가상 머신으로 정보가 저장된다. 혹여 Codespace를 중지 하더라도 향후 저장된 시점으로 불러와 작업을 이어하면 되지만, 아닐경우 작업 내용 손실을 방지하고자 사전에 커밋 요청 메시지가 표시되어 방지 기능이 활성화 된다.

> [!WARNING]
> **Codespace가 삭제되면 저장 전 작업 내용들은 소실되며 사라지기 때문에 작업을 저장 후 변경 내용에 대한 커밋을 진행 이후에 해당 리포지토리에 푸시하거나 복사한 템플릿의 Codespace인 경우 새 리포지토리에 게시해야 한다.**

## Codespace 작업 방식

### 기존 Codespace 열기

활성 또는 중지된 Codespace는 GitHub.com, JetBrains, Visual Studio Code, GitHub CLI에서 다시 열 수 있으며 기존 작업을 다시 시작하려면 Codespace가 있는 리포지토리로 이동해 키`,`를 선택 후 다시 시작을 선택할 수 있다.

### 작업 시간 제한

비활성 상태이거나 사용자가 명시적으로 중지하지 않고 종료한 경우, 비활성 기간이 지나면 애플리케이션은 시간이 초과되고 실행이 중지된다. 기본 시간 제한은 비활성 상태가 시작된 후 30분으로 시간 초과에 대한 변경 내용이 마지막으로 저장된 시점의 데이터가 보존된다.

### 종료 또는 중지

중지 명령을 실행하지 않은 상태에서 종료하거나 상호 작용 없이 Codespace를 장기간 실행 상태로 두면 실행 중인 프로세스는 비활성 시간 제한 범위에 유지될 수 있다. 기본적으로 비활성에 대한 제한은 [`Codespace 작업 시간 제한`](#codespace-작업-시간-제한)에 해당되지만, 별도로 사용자가 생성한 Codespace에 대한 개인 시간 제한 설정을 정의할 수 있다. 다만 이러한 설정은 조직 시간 제한 정책에 따라 불가할 수 있다.

> [!WARNING]
> **실행 중인 Codespace에서만 CPU 사용량 비용이 발생하며 중지된 Codespace는 스토리지 비용만 발생한다.**

변경 내용을 적용하려면 기존 Codespace를 중지 후 재시작해야 하며, 컴퓨터 유형을 변경하는 경우나 기타 사유로 변경 내용을 적용하려면 중지 후 다시 시작하는 과정을 거쳐야 한다. 따라서 커밋되지 않은 모든 변경 내용은 Codespace에 다시 연결할 때까지만 유지된다.

### 재빌드

다시 빌드하여 개발 컨테이너 구성에 대한 변경 내용을 구현할 수 있다. 대부분의 경우에는 Codespace를 다시 빌드하는 대신 새 Codespace를 생성하면 되고, 다시 빌드하면 캐시의 이미지의 효율성을 장점으로 재빌드 프로세스 속도가 상승한다. 이는 곧 전체 재빌드를 수행하여 캐시를 지우고 새 이미지를 이용해 컨테이너를 재빌드할 수 있다.

### 삭제

특정 작업에 대한 Codespace를 삭제할 수 있다. 변경 내용을 원격 분기에 푸시한 경우에만 해당되며 푸시되지 않은 커밋 내용이 있다면 작업중인 해당 분기에 미 푸시된 변경 내용이 있다는 메시지와 함께 표시된다. 원하는 변경 사항을 푸시했다면 더 이상 Codespace의 작업이 포함되지 않기에 비용이나 혹은 리소스 충돌을 방지하고자 삭제하는 것을 권장한다. 하지만 커밋되지 않은 변경 내용을 계속 삭제하거나, 새 Codespace를 생성하지 않고 코드를 새 분기로 내보낼 수 있다.

> [!TIP]
> **중지된 Codespace는 지정된 시간 동안 비활성 상태가 유지되면 자동으로 삭제 프로세스가 진행되며, 비활성 Codespace는 30일 후에 삭제되지만 보존 주기는 사용자의 별도 지정이 가능하다.**

## Codespace 개인 설정

GitHub Codespace는 사용자를 위한 전용 환경으로서 개발 컨테이너를 사용해 리포지토리를 구성하여 기본 GitHub Codespace 환경을 정의하고, dot 파일 및 설정 동기화를 사용한 모든 Codespace에서 개발 환경을 커스터마이즈할 수 있다.

### 사용자 설정 지정 항목

* 설정 동기화
  * 데스크톱 애플리케이션과 VSCode 웹 클라이언트 간의 설정을 동기화 가능
* Dot 파일
  * Dot 파일 리포지토리를 사용하여 스크립트, 셸 기본 설정 및 기타 구성 지정
* Codespace 이름 변경
  * 자동 생성된 표시 이름이 할당되며, 여러 Codespace가 있는 경우 표시 이름을 사용하여 구분할 수 있고 이름 변경도 가능하다.
* 셀 변경
  * 셸을 변경하여 사용자에게 익숙한 설정으로 유지할 수 있다 작업할 때는 선택한 셸이 있는 새 터미널 창을 열거나, 새 터미널 창의 기본 셸을 변경하거나, 설치할 수 있으며 Dot 파일을 사용하여 셸을 구성할 수 있다.
* 컴퓨터 유형 변경
  * 실행하는 컴퓨터의 유형을 변경하여, 수행 중인 작업에 적합한 리소스를 사용
* 편집기 설정
  * 개인 설정 페이지에서 Codespace 기본 편집기를 설정할 수 있으며, 생성하거나 기존 Codespace를 오픈할 때 기본 편집기에서 열리도록 편집기 기본 설정을 지정 [`VSCode`,`VS`,`JetBrains`,`JupyterLab`, `...etc`]
* 기본 지역 설정
  * GitHub Codespace 설정 페이지에서 기본 지역을 설정하여 데이터가 보관되는 위치를 개인 설정
* 시간 제한 설정
  * 지정된 비활성 기간이 지나면 Codespace의 실행이 중단되기 때문에 기본 비활성 유지 기간은 30분이지만, 개인 설정에서 더 길거나 짧은 기본 시간 제한을 지정하여 업데이트된 설정은 새로 만든 모든 Codespace에 적용 [`최대 30일`]
* 자동 삭제 구성
  * 비활성 Codespace가 자동으로 삭제 및 중지된 Codespace가 보존되는 기간을 선택
